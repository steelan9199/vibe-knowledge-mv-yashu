# 抽帧的 --t 是全片归一化，不是镜内进度

## 症状

排查第 4 镜海面，`node scripts/shot.mjs --html out/story.html --t 0.30` 抽了一帧，裁 `crop=960:230:0:790` 放大，看到 4 层浪峰确实有尖齿，于是一路在 `smoothD` / `rim` 上找了半天。

后来列分镜表才发现：全片 24.10s，9 镜分别占 `0~3.60 / 3.60~5.70 / 5.70~7.40 / 7.40~10.40 …`。**`t=0.30` 对应 7.23s，落在第 3 镜 `miss` 的尾巴上**，第 4 镜要到 `t≥0.307` 才开始。看的是隔壁镜头的海面。

## 根因

`?t=` 由页面按 `t * duration` 换算全片时刻，**不是镜内 0~1 进度**。这个参数名太自然，容易被当成「这一镜的进度」。第 4 镜中段实际是 `t = (7.40 + 1.5) / 24.10 = 0.369`。

## 修法

抽帧前先算：

```bash
node -e "
const fs=require('fs'); const h=fs.readFileSync('out/story.html','utf8');
const s=JSON.parse(h.match(/window.STORY = (\{[\s\S]*?\});/)[1]);
let c=0; s.scenes.forEach((x,i)=>{console.log(i+1,x.type,c.toFixed(2)+'~'+(c+x.dur).toFixed(2)); c+=x.dur;});
"
# t = (cumStart + dur/2) / total
```

这条命令已写进 `SKILL.md` §5 的提示。**抽帧位置错了，后面所有判断都是错的**，而且错得很安静——隔壁镜也有海。
